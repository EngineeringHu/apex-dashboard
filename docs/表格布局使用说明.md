# 表格独立布局

表格文字、任务、行列和合并关系继续保存在 Markdown 中。列宽、行高及表格分区的显示高度保存在插件 `data.json` 的 `tableLayouts` 中，按工作台文件及表格分区隔离。调整显示尺寸不会修改 Markdown，也不会触发周记内容加密保存。

## 操作

- 拖动表格顶部数字刻度之间的边界调整列宽；拖动左侧短横线调整对应行的高度。合并单元格按覆盖的基础行列计算尺寸。
- 双击边界恢复该行或列的自动尺寸。拖拽时按 Esc 或取消指针操作会恢复拖拽前的尺寸。边界获得键盘焦点后，可以用方向键以 10px 为步长调整。
- 文字自动换行，行高作为内容的最低高度，内容较多时仍会撑开。列宽保留最低可读宽度。
- 工具栏切换“随内容展开”和“限定并滚动”；拖动分区底边设置高度上限。首次打开旧表时，仅参考已有 `height`，后续调整不再写回该字段。
- “恢复自动布局”清除手动行高和列宽，并切换为随内容展开。
- 自动列宽跟随表格所在面板的宽度。面板过窄时在表格内部横向滚动；手动列宽不会随窗口变化缩小。

## 行列变更

通过工作台右键菜单增删行列时，新行列取得独立布局 ID，其余行列保留原来的 ID 与手动尺寸。合并结构、任务编辑、任务拖拽和删除行列后的未放置卡片仍沿用已有机制。

直接编辑 Markdown 或在“编辑表格”窗口整体替换内容时，按内容摘要协调行身份，按识别到的周计划表头摘要协调列身份（普通表格参考前两行）。能够唯一匹配的保留尺寸；重复空白行、重复表头或无法匹配的部分恢复自动尺寸。第一版不会推测复杂外部变更的意图，也没有新增行列重排功能。

布局配置不保存单元格明文，但包含行数、列数、尺寸、匹配摘要与文件/分区关联信息。普通分区按名称与同名出现次序关联，加密分区使用已有的加密块 ID。应用内文件/文件夹重命名以及工作台内分区重命名会迁移关联；外部修改分区名称后从自动布局开始。复制到新路径的工作台使用独立默认布局，暂不自动继承旧文件的手动尺寸。

布局保存在插件配置中，随该配置的同步策略同步。丢失布局配置只会恢复自动排版，不影响笔记内容。加密开关将文件转换为另一种文件格式时，第一版不跨格式迁移自定义布局。

## 验证与预览

- `npm test`：类型检查、构建及原有内容/加密回归。
- `npm run test:table-layout`：尺寸与行列身份、外部修改协调、独立持久化、重新加载、路径迁移和保存重试。
- `npm run test:upstream`：包含表格布局及待办卡片相关回归。
- `scripts/verify-table-layout-ui.ts` 与 `scripts/test-table-layout-ui-inapp.js`：使用项目规定的 Windows Obsidian CLI 运行合成界面测试，报告写入 `test-output/table-layout-ui.json`，并检查真实笔记哈希。
- `scripts/preview-table-layout.ts`：真实 Obsidian 中的临时交互预览，示例内容和布局只在内存保存，关闭即清理，不部署正式插件。

固定表头、固定首列和专注视图未包含在本次实现中。
