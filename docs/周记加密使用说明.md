# 周记加密使用说明

版本：`2.2.1-secure.5`，2026-10-02。现在使用一个全局加密开关；旧的临时解密、临时附件解密和结束临时模式入口已移除。

## 使用入口

**设置 → Apex Dashboard → 常规 → 周记加密**。

- **开启**：将“周记”目录直属的全部周记转换为 `.apexenc`，不转换配置中的模板。保留原工作台样式；每个分区展开时输入密码，收起时保存密文并锁定。新建跟随此开关，创建密文且无需输入密码。
- **关闭**：输入一次统一密码，将所有加密周记转换为普通 `.md`，附件恢复至 `周记/_附件/`。工作台、Markdown 编辑、原生搜索和 Dataview 按普通笔记使用。重启、闲置、收起或关闭工作台都不会重新加密；只有再次打开加密开关才转换回密文。
- 如果更新前目录同时存在普通周记和加密周记，设置页会显示“现有周记格式尚未统一”，可一键应用当前开关到全部周记。安装更新本身不会自动转换你的现有文件。

关闭加密后，Windows 和 Git 都能读取普通明文文件。这些文件不是临时副本，不会自动清理。

## 统一密码与文件名

同一设置页的 **周记统一密码 → 设置 / 更改密码** 提供统一密码入口，也可执行命令 **周记加密：设置或更改统一周记密码**。

最低 3 个字符。首次设置时，有旧加密周记则先验证原密码，再设置统一密码并确认。设置一次后，新建周记使用公钥加密，不再输入密码；展开分区、整篇编辑和关闭加密开关仍需验证密码。配置中保存公钥和由密码加密的私钥，没有明文密码。

文件名直接使用输入的名称，例如 `第3周-10月1号.apexenc` 或关闭后的 `第3周-10月1号.md`。同名文件自动加 `-2` 等后缀，不覆盖现有文件。可通过 **恢复旧文件名** 将以前的随机文件名恢复为密文中的原名称。

更改统一密码会逐篇验证并更新当前密文。中断后会自动继续密码更新，也可使用“恢复统一密码更新”命令。Git 历史中的旧密文仍使用旧密码。

## 工作台编辑

两种模式都沿用原 Apex 布局、侧栏、周计划表、备忘和任务编辑器。

加密开启时，分区编辑直接保存为密文；再次展开仍需密码。支持原有表格勾选、任务增删、备忘编辑、卡片、分区高度和改名等操作。新增、删除和排序分区需要验证密码更新清单。跨分区移动内容前，先解锁目标分区。

分区头部可编辑 Markdown 原文或导入加密附件；页签右上角可验证密码后编辑整篇 Markdown。导出普通笔记、保存到日记和归档等操作会提示它们将产生普通明文。

开启加密时，尚未验证密码的分区先使用模板提供标题和外观；解锁后载入密文中的实际标题和布局。收起清除正文视图和对应解锁会话，多标签页同一分区同步锁定。

## 切换时的数据处理

1. 保存并关闭涉及转换的编辑视图。
2. 按文件逐个准备、验证转换结果；新旧文件同时存在的过渡阶段不会报告完成。
3. 所有目标文件写入并校验通过后，才删除对应的旧文件。
4. 完成后保存开关状态并打开转换后的周记。开启时清理已转换 Markdown 的 Dataview 内存和持久索引。

转换记录和内部暂存只保存密文、路径及校验值，不保存密码或正文。断电、退出或写入失败时，设置页显示 **继续切换**；恢复完成前阻止重复转换或新建。关闭方向恢复需要再次输入密码。不要手工删除未完成的转换记录或相关文件。

切换期间若文件被 Git 或其他程序改动，会停止而不覆盖。完成切换后再提交同步。普通 `.md` 模式不做缓存抑制；开启时的 Dataview 缓存清理已适配 0.5.68，其他版本需先验证或停用后切换。

图片和附件跟随转换。启用前会检查附件是否被转换范围之外的 Markdown 引用；共用附件会阻止切换并提示引用笔记，避免删除其他笔记需要的文件。请为周记准备独立附件后重试。远程嵌入图片、缺失附件及嵌入其他 Markdown 需先处理。单附件上限 32 MiB，单篇正文上限 4 MiB。

历史 Git 明文、Apex 备份、其他插件生成的副本及操作系统缓存不属于此次切换清理范围。

如果旧版本留下未结束的临时解密记录，只会显示一次性的“完成旧版遗留数据恢复”入口，用于保全旧编辑；恢复后不再提供临时模式。

## Git 与其他 Windows 电脑

同步以下文件及本库正常笔记：

```text
.obsidian/plugins/apex-dashboard/main.js
.obsidian/plugins/apex-dashboard/secure-worker.js
.obsidian/plugins/apex-dashboard/styles.css
.obsidian/plugins/apex-dashboard/manifest.json
.apex-weekly-keyring.json
.apex-weekly-mode.json
tools/decrypt-weekly.mjs
tools/apex-crypto.mjs
周记/*.apexenc 或 周记/*.md
周记/_assets/*.apexasset
周记/_附件/ （关闭加密时的普通附件）
```

密钥配置在设置密码后生成，开关配置在首次完成切换后生成。两者均需同步。其他电脑拉取后启用同版插件并重启，可读取相同开关状态并新建笔记；无需原 Windows 账户。不要用社区上游版覆盖此定制版本。

保留 `.gitignore` 和 `.gitattributes`。内部转换暂存和未完成操作记录禁止同步；密文和密钥配置禁止自动合并。`tools/check-protected-git.mjs` 可作为提交前检查，在转换未完成时阻止提交；需由每台电脑的 Git hook 调用，本次没有变更 hooks 或执行提交推送。

关闭期间提交的普通 Markdown 会保留在 Git 历史里，再次开启不会改写历史。

## 不使用 Obsidian 时解密

Node.js 20+，无需 npm 包。工具兼容旧版 v1 和当前 v2 密文；文件内嵌密码保护的恢复信息，不依赖 Obsidian 配置。

```powershell
node tools/decrypt-weekly.mjs "周记/第3周-10月1号.apexenc" --verify
node tools/decrypt-weekly.mjs "周记/第3周-10月1号.apexenc" --output "D:/私密导出/周记.md" --with-assets
```

终端交互输入密码，不回显。保留 `周记/_assets/` 以恢复附件。工具不覆盖已有输出、不删除原密文；主动导出内容是普通明文。

已通过构建、TypeScript 检查和密码学/存储回归。真实 Obsidian 自测使用隔离的合成笔记，覆盖：

- 开关关闭、重新开启、普通模式重载后保持关闭。
- 错误密码和取消不删除原文件，同名防覆盖。
- 正文及图片附件双向转换，普通工作台表格勾选保存。
- 原生元数据及 Dataview 普通索引、开启加密后的索引清理。
- 关闭时注入写入失败、开启时注入明文清理失败，以及重载后继续恢复。
- 加密结果解密后与转换前已保存 Markdown 完全一致。

报告：`项目目录 test-output/mode-inapp.json`。测试清理后核对原有笔记哈希不变。早期分区编辑、整篇编辑、多标签页锁定的回归报告仍保存在同目录。

密码派生和加解密在 Web Worker 内完成；转换按文件串行并显示进度，启动不会批量转换。大库切换的磁盘 I/O、索引耗时及其他电脑性能仍需结合实际规模观察。没有独立安全审计，不能保证 JavaScript 或操作系统内存立即物理清零。
## 使用加密看板模板

在 Apex 设置的“新建看板模板文件”中点击“选择模板”，可选择 `.md` 或 `.apexenc`。也可以填写库内完整路径，例如 `模板/周计划.apexenc`；省略扩展名时先查找 Markdown，再查找同名加密文件。

每次启动 Obsidian 后，首次使用加密模板新建看板时输入模板密码；本次插件会话内后续新建免输。模板解锁状态仅保存在内存中，不保存密码。重启、重新加载插件、切换模板、修改/重命名/删除模板或点击“锁定模板”后，需要重新解锁。命令面板也提供“周记加密：锁定加密看板模板”。

新周记格式跟随周记加密开关：开启时生成加密周记并复制加密附件，关闭时生成普通 Markdown 和普通附件。模板的表格、任务分区、布局配置和正文会被保留。配置中的模板文件不计入周记列表和周序号，也不参与全体周记加密开关转换。

加密模板有附件时须一起保留对应的 `_assets` 文件夹；模板旁没有附件时会查找 `周记/_assets`。首次解锁会校验附件，缺失或损坏会阻止新建，避免产生残缺看板。新建不会修改原模板，错误密码或取消不会创建看板。

该功能在使用模板时按需解锁，启动时不扫描或解密全部周记；加密计算继续在 Web Worker 执行，附件按顺序复制。
